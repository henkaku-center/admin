Revitalized Henkaku & SDS Websites

Architecture proposal — April 2026

1. High-Level Architecture

Two public-facing sites backed by the existing Registry API. Content is a mix of editable CMS pages (landing, about, articles) and live data pulled from Compass entities.

4. Contributor Workflow

Two contribution paths: technical contributors edit entities via Compass, editorial contributors write articles via Decap CMS. Both feed the same built site.

sequenceDiagram
    participant Editor as Article Author
(e.g. Joseph Park)
    participant CMS as Decap CMS
    participant Git as GitHub Repo
    participant GHA as GitHub Actions
    participant Site as Public Website

    Editor->>CMS: Write feature article (Markdown)
    Editor->>CMS: Link to compass entities by ID
    CMS->>Git: Commit article .md file
    Git->>GHA: Push triggers build
    GHA->>Site: Deploy updated static site

    participant Member as Community Member
    participant Compass as Compass App
    participant Registry as Registry API

    Member->>Compass: Update own profile / project
    Compass->>Registry: PATCH /compass/entities/{id}
    Registry-->>GHA: Webhook triggers rebuild
    GHA->>Site: Deploy with fresh entity data

5. Two Sites, Shared Codebase

A single Astro monorepo with shared components and per-site configuration. Each site gets its own branding, landing page, and content subset.
